# 来源核查协议（verification protocol）

这是本套件的核心。**没有来源的事实不许写成事实；核不了的写 `[未验证]`。**

## 1. 适用范围

| 类型 | 例子 | 最小可接受证据 |
|---|---|---|
| 引用文献 | 作者、年份、标题、期刊、卷期页、DOI | DOI 可解析的出版社页面，或 PubMed/Crossref/OpenAlex/Semantic Scholar 的条目 |
| 统计数据 | 百分比、样本量、增长率、影响因子、分区 | 原始数据表、论文表格、官方统计页（政府/机构） |
| 期刊/会议政策 | 字数、格式、AI 披露、伦理要求、开放获取 | 该 venue 官网的 Author Guidelines / AI Policy 页面 |
| 方法学断言 | "X 方法在此类任务上是标准做法" | 教科书、领域综述、权威指南（并给出处） |

## 2. 状态定义

| 状态 | 含义 | 判定条件 |
|---|---|---|
| `已核实` | 来源直接支持该声明 | 数字一致、对象一致、方向一致；允许标点/措辞差异 |
| `部分核实` | 只支持一部分 | 必须写出"哪一部分一致、哪一部分不一致" |
| `未验证` | 没找到可靠来源，或只有转引 | 检索不到、来源无法打开、只有二手描述 |
| `与来源冲突` | 来源明确给出相反结论/数字 | 正文必须显式提示差异，不能悄悄改数字 |

只有这四种。不要自造"基本可信""大体准确"之类中间态。

## 3. 执行流程（逐条）

1. **抽取**：把正文里可核验的声明切出来，编号 `E1, E2, …`。
2. **检索**：用标题+作者，或 DOI 直查。中文文献用中文标题+作者。
3. **打开原始页**：`web_fetch` 打开 DOI 落地页或官方指南，**不要只看搜索摘要**。
4. **比对**：作者、年份、期刊、卷期页、DOI、数字、结论方向，逐项打勾。
5. **记录**：填证据核查表（见第 5 节），写核验日期（本地时区）。

任一步失败 → 状态降级为 `未验证`，保留已知信息，写清"差在哪一步"。

## 4. 检索技巧

- DOI 直查：`https://doi.org/<doi>`；查不到就试 Crossref `https://api.crossref.org/works/<doi>`。
- 找 DOI：Crossref / OpenAlex / Semantic Scholar 搜标题；注意同名不同文。
- 撤稿/更正：查出版社页面的 Retraction/Correction 提示，以及 Retraction Watch。
- 论文里的统计数字：优先打开原文表格，不要引用二手综述里的数字。
- 期刊政策：官网 "Instructions for Authors"、"AI use policy"、"Ethics" 三个词分别搜一次。
- 影响因子/分区：JCR 与中科院分区都是商业产品，**只有官网/机构订阅页能确认**；拿不到就标 `未验证`，不要在正文写具体数值。

## 5. 证据核查表（交付物必备）

```markdown
## 证据核查

| ID | 声明/条目 | 类型 | 来源 | 核验日期 | 状态 | 备注 |
|---|---|---|---|---|---|---|
| E1 | Smith (2023) 报告 42% 增长 | 引用 | https://doi.org/10.xxxx/xxxx | 2026-10-22 | 已核实 | 数字见原文表 2 |
| E2 | 该刊 2025 影响因子 3.1 | 统计 | 未找到官网页 | 2026-10-22 | 未验证 | 仅见聚合站，不可引用 |
```

字段约定（脚本按此检查）：

- `类型` ∈ 引用 / 统计 / 政策 / 方法
- `状态` ∈ 已核实 / 部分核实 / 未验证 / 与来源冲突
- `已核实`、`部分核实` 必须有可解析来源（http/doi/用户提供）
- `来源` 写 "用户提供，未独立核验" 时，正文中不得当作外部事实引用

## 6. 部分核实与冲突怎么写

- 部分核实：`[部分核实] 原文报告 38%，转引来源写 42%（差异见 E1）`
- 冲突：`[与来源冲突] 本稿写 42%，但 E1 原文为 38%，需作者确认` —— 同时给出建议处理方式，不擅自改。
- 未验证：`[未验证] 据称 A 方法优于 B（未找到来源）`

## 7. 预算与降级

- 单轮 ≤ 8 次外部检索。
- 预算用尽：剩余条目统一 `未验证`，备注写"本轮预算内未核完"。
- 用户要求"先给结论后补核"：正文统一加"未核验"段落头，核查表照常登记。

## 8. 常见错误

| 错误 | 为什么错 | 正确做法 |
|---|---|---|
| 凭记忆补 DOI/卷期页 | 最常见的编造来源 | 只写能打开的来源，其余留空并标未验证 |
| 用搜索摘要当来源 | 摘要可能张冠李戴 | 打开落地页再比对 |
| 检索不到就写"不存在" | 检索不到≠不存在 | 写 `未验证` |
| 把二手综述的数字当原文数字 | 数字可能被转写错 | 追到一手来源或写"转引自" |
| 编造影响因子/分区 | 商业数据库无公开页 | 标未验证，正文不写具体数值 |
| 把期刊"常理"当政策 | 政策逐年变 | 查当年官方页面 |

## 9. 交付前自检

跑：

```powershell
python scripts/verify_checklist.py <交付文件.md>
```

它会检查：有没有证据核查表、状态是否合法、已核实条目是否带来源、未验证条目是否被列出。有违规先修，再交付。
