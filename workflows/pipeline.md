# workflow: pipeline（端到端）

适用：从选题到可投稿稿件的完整流程，或从任意阶段进入。
不适用：只做单点任务（写摘要、查引用）→ 直接去对应 workflow，不要开流水线。

需要的角色：`research-question`、`draft-writer`、`methodology-reviewer`、`devils-advocate`、`editor-in-chief`、`revision-coach`、`citation-auditor`
需要的参考：`ai-failure-modes.md`、`verification-protocol.md`、`review-rubric.md`
输出模板：`research-brief.md`、`review-report.md`、`decision-letter.md`、`revision-roadmap.md`、`evidence-table.md`

## 阶段

| Stage | 名称 | 产物 | 关卡 |
|---|---|---|---|
| 0 | intake | 一页任务卡：目标 venue、材料、约束、成功标准 | 用户确认 |
| 1 | research | RQ Brief + 检索与证据矩阵 | RQ/策略确认 |
| 1.5 | experiment（可选） | 实验方案或数据说明 | 方案确认 |
| 2 | write | 大纲 → 分节初稿 | 大纲确认、每节可插改 |
| 2.5 | integrity gate | 完整性报告（强制） | 必须处理 |
| 3 | review | 3 审稿人 + 魔鬼代言人 + 决定信 | 用户决定是否返修 |
| 3′ | re-review | 核销与回归检查 | — |
| 4 | revision | 修订稿 + 改动说明 + 回复信 | 用户确认 |
| 4.5 | integrity re-check | 复核 2.5 的问题是否清零（强制） | 必须处理 |
| 5 | finalize | 格式、引用、披露、投稿包清单 | 投稿前确认 |
| 6 | summary | 过程记录 + 未解决风险 | — |

## 进入方式

- 从 0 开始：用户说"完整写一篇/从选题到投稿"。
- 从 2.5 进入：已有初稿，先做完整性检查再决定下一步。
- 从 4 进入：已有审稿意见，直接返修。

用户只给宽泛题目 → 不进流水线，先走 `deep-research.md` 的 socratic。

## Stage 2.5 / 4.5 完整性闸门（不可跳过）

逐项检查，每项给"通过 / 存疑 / 不通过 + 证据"：

1. **引用幻觉**：每条参考文献核 DOI/标题/作者/年份；相似度不足即存疑。
2. **数字捏造**：正文每个统计数字能追到来源或用户数据。
3. **方法造假**：写的方法与实际做的一致（用户材料为准）。
4. **结果与结论错位**：结论强度不超过证据强度。
5. **捷径依赖**：是否只在易测子集上评估却下全局结论。
6. **框架锁定**：是否只在一个框架内自证，没有反例处理。
7. **可复现性**：参数、数据、环境是否足够复现。

规则：

- 2.5 标"存疑"的项，必须在 4.5 变成"通过"，或用户明确接受并记录理由。
- 闸门结果进《证据核查表》，不另开一套状态词。
- 闸门不通过时，不要继续往 5 走。

每阶段开始时输出：

```

输入: <已有材料>
本次产出: <一个产物>
风险: <当前最大风险>
下一关卡: <确认什么>
```

## 注册点与范围控制

- 一次只推进一个 Stage。
- 用户说"全部跑完" → 连续推进，但 2.5、4.5、5 三个关卡必须停。
- 任何阶段发现 RQ 有问题 → 回到 Stage 1，不要带病往下写。
- 不新增用户没要的交付物（如额外做 PPT、额外做英文版）。
