# workflow: deep-research（研究前期）

适用：研究问题提炼、文献综述、系统综述/PRISMA、Meta 分析、事实核查、三路扫描。
不适用：论文写作与审稿 → 用 `academic-paper.md` / `paper-reviewer.md`。

需要的角色：`socratic-mentor`、`research-question`、`synthesis`、`citation-auditor`
需要的参考：`verification-protocol.md`、`evidence-levels.md`
输出模板：`research-brief.md`、`literature-matrix.md`、`evidence-table.md`

## 模式

| 模式 | 触发 | 做什么 | 产出 |
|---|---|---|---|
| socratic | 宽泛选题、无明确 RQ | 追问收敛，不产出大纲 | RQ Brief（候选 RQ + 范围 + 贡献假设） |
| quick | "快速了解一下" | ≤1 页要点 + 3–5 条关键来源 | 简报 |
| lit-review | "做文献综述" | 主题聚类 + 矩阵 + 综合 | 文献矩阵 + 综述草稿 |
| systematic-review | "系统综述/PRISMA" | 协议 → 检索 → 筛选 → 提取 → 偏倚风险 → 综合 | 协议 + PRISMA 流程 + 纳入表 |
| meta-analysis | "Meta 分析" | 效应量、异质性、合并结果表 | 数据表 + 异质性说明 |
| fact-check | "核对这几条说法" | 逐条给 verdict | 声明-来源-状态表 |
| three-way-scan | `ars-3w`、"三路扫描" | WHY / HOW / WHAT 三列对比 | 对比表 |
| full | "完整调研" | 上面全链路 | 全部产物 |

## full 模式阶段

1. **范围与意图**：学科、目标读者、时间窗、语言、用途（开题/投稿/评审）。缺关键项就问，最多 3 个问题。
2. **研究问题**：用 `research-question` 角色卡；输出 1 个主 RQ + 2–3 个子问题 + 贡献假设。**关卡：RQ 确认。**
3. **检索策略**：数据库、检索串、时间窗、语言、纳入/排除标准。检索串必须可复现地写出来。**关卡：策略确认。**
4. **筛选**：标题/摘要 → 全文两步；记录每步数量。
5. **证据提取**：每篇一行（见 `literature-matrix.md`）：研究设计、样本、方法、主要结论、局限、与 RQ 的关系。
6. **核查**：用 `citation-auditor` 逐条核 DOI/标题/作者/年份；不通过的不进表。
7. **综合**：主题聚类 → 证据强度 → 冲突 → 缺口 → 可检验的研究机会。
8. **交付**：RQ Brief / 矩阵 / 综述 / 证据核查表 / 未验证清单。

## socratic 模式规则

- 第一句先说明：因为研究问题还不精确，先做问题收敛，暂不写大纲。
- 每轮只问 2–3 个问题，覆盖：现象与边界、已有解释、数据可得性、贡献点。
- 用户想跳过 → 说明代价，给一版"临时 RQ"继续，但标注"未收敛"。
- 收敛后输出 RQ Brief，再问是否进入下一阶段。

## 系统综述硬规则

- 协议先于检索：先写清 RQ、PICO/PEO、纳入排除、结果指标、偏倚评估工具。
- PRISMA 计数自洽：识别数 − 去重 − 排除 = 纳入数，任一环节对不上就先查。
- 每篇纳入研究必须有可解析的 DOI 或稳定 URL；只有摘要的标"仅摘要，未读全文"。
- 偏倚风险按研究设计选工具，工具名与实际设计不符就说明。
- 不做"手工统计"：需要合并效应量时给数据表与计算口径，交由脚本/统计工具，结果标"待核"。

## 事实核查模式

逐条处理，不要合并：

| # | 声明（原文） | 类型（引用/统计/政策/方法） | 来源 | 状态 | 说明 |
|---|---|---|---|---|---|

- `已核实`：来源直接支持原声明，允许措辞差异，不允许数字差异。
- `部分核实`：来源支持一部分（如样本对、结论方向对，但数字不同），必须写出差在哪。
- `未验证`：没找到可靠来源，或只找到转引。
- `与来源冲突`：来源明确给出不同数字/结论。

## 检索预算

单轮 ≤ 8 次外部检索。预算内没核完的条目，统一标 `未验证`，在核查表里写"本轮检索预算内未核完"。
