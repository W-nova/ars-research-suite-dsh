# workflow: experiment-design（实验与数据）

适用：实验方案、代码实验计划、人类研究协议、统计解读、可重复性检查。
不适用：编造实验结果。这个套件**不替你跑实验**，只做方案与解读。

需要的角色：`methodology-reviewer`
需要的参考：`verification-protocol.md`（统计数字核查）
输出模板：`research-brief.md`

## 模式

| 模式 | 触发 | 产出 |
|---|---|---|
| plan | "设计实验" | 假设 → 变量 → 基线 → 指标 → 消融 → 预算 |
| protocol | "人类研究/问卷/访谈" | 研究协议 + 伦理核查清单 |
| stats | "这个结果怎么解读" | 解读报告 + 替代解释 + 不成立的说法 |
| reproducibility | "能不能复现" | 复现清单 + 缺口 |

## plan 输出结构

1. **假设**：H1 可检验表述 + 零假设 + 什么结果会证伪。
2. **变量**：自变量、因变量、控制变量、混杂与处理方式。
3. **基线**：至少 2–3 个强基线 + 1 个简单基线；说明为什么公平。
4. **指标**：主指标 1–2 个 + 次指标；说明方向（越高越好/越低越好）。
5. **消融**：每个核心组件一组消融；先列"如果没有它，预期掉多少"。
6. **样本与检验力**：样本量依据（先验/功效分析），不要拍脑袋。
7. **随机与种子**：随机化方式、随机种子数、报告均值±方差。
8. **预算**：算力/被试/时间上限；超出要先说。
9. **预注册项**：哪些分析是事先定的，哪些是探索性的（探索性必须标注）。

## protocol（人类研究）核查清单

- [ ] 研究目的与最小风险说明
- [ ] 招募渠道、纳入/排除标准
- [ ] 知情同意流程（语言、退出的权利）
- [ ] 数据最小化：收什么、存哪、存多久、谁可访问
- [ ] 匿名化/去标识化方案
- [ ] 伦理审批状态：**未获批就标"待批"，不要写成已批准**
- [ ] 风险与应急预案

不提供法律或伦理裁定；只做清单与提醒。

## stats 解读规则

先说结论边界，再谈数字：

1. 先问：这个设计能回答这个问题吗？不能就先说不能。
2. 区分：描述统计 / 推断统计 / 因果断言。
3. 常见解读错误（逐条自检）：
   - 把 p 值当效应大小
   - 把"不显著"当"无效应"
   - 多重比较不校正
   - 相关当因果
   - 用 R² 论证因果
   - 选择性地报告子组
   - 把置信区间读成概率
   - 忽略缺失数据机制
   - 把统计显著当实践重要
   - 用"趋势显著"描述 p≈0.06
   - 事后改假设（HARKing）
4. 每个断言标：`数据支持` / `数据不支持` / `数据不足`。
5. 数字必须能追到来源：用户数据（标"用户提供"）或已核实文献（标 DOI）。

## reproducibility 输出

- 环境：语言/版本/依赖锁定方式
- 数据：来源、许可、划分方式、预处理脚本
- 运行：命令、随机种子、硬件
- 结果：期望输出与校验方式
- 明确写一句：**本文档是配置记录，不是"可重放保证"**；LLM 参与的部分本身不可字节级复现。

## 关卡清单

- [ ] 假设可证伪
- [ ] 基线公平且足够强
- [ ] 主指标唯一且事先定
- [ ] 样本量有依据
- [ ] 统计解读未越界
- [ ] 伦理状态如实标注
